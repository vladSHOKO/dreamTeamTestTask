# Тестовое задание Dream Team

## Установка модуля

1. Склонируйте репозиторий в папку local/modules на вашем сайте в папку **dreamteam.test**
2. Выполните стандартную установку модуля через админку (Marketplace->Установленные решения->dreamteam.test->Установить)

### Подключение маршрутов

Установщик копирует `dreamteam.test.php` в `/local/routes/` и добавляет его в `routing.config` основного `.settings.php`. При деинсталляции он удаляет файл и запись из этого списка.

Если сайт переопределяет секцию `routing` в `.settings_extra.php`, после установки добавьте `dreamteam.test.php` в список `routing → value → config` в этом файле, чтобы подключить API. После деинсталляции эту запись можно удалить вручную.

## Примеры запросов

```bash
BASE_URL='http://some_address.ru'
```

Создать новость:

```bash
curl "$BASE_URL/api/news/add" \
  -H 'Content-Type: application/json' \
  --data '{"name":"Тестовая новость","code":"test-news","description":"Описание новости"}'
```

Получить список с фильтрами. Все фильтры необязательны, даты передаются в формате `YYYY-MM-DD`.

```bash
curl -G "$BASE_URL/api/news/list" \
  --data-urlencode 'name=Тестовая' \
  --data 'date_from=2026-01-01' \
  --data 'date_to=2026-12-31'
```

Получить новость по ID. Подставьте `id` из ответа на создание.

```bash
NEWS_ID=123
curl "$BASE_URL/api/news/$NEWS_ID"
```

## Комментарии по реализации

- При публикации модуля на маркетплейс Битрикса нужно было бы изменить названия ключевых методов в install/index.php с camelCase на PascalCase, потому что обфускатор битрикса(обфусцируются платные модули) ломает установку, если названия методов заданы не корректно. А также добавить закрывающий тег ?> в include.php
- Для такого простого задания можно было всю логику работы с БД описать в одном сервисе, однако всё же решил выделить бизнесовый сервис и слой обращения к данным
- Для удобства работы с запросами было решено вынести запросы в отдельные модели. Таким образом мы получаем понятную структуру запроса и удобную валидацию входных параметров
- Для тестового задания авторизация и проверка токена были нарочно отключены для удобного тестирования. Иначе пришлось бы проходить авторизацию на портале и вписывать данные в параметры запроса, что не сложно реализовать, но для тестового мне показалось лишним
- Для модуля была сделана установка инфоблока и его типа. Конечно в задании код инфоблока достаточно типовой. Если бы речь шла про решение рабочих задач, то я бы склонялся к более уникальному коду инфоблока и его типа
- Для создания инфоблока был выбран классический подход, потому что IblockTable::add() не создаёт таблицы свойств для версий хранения 2, не назначает права и тд. На использование классического подхода также указывает сам Битрикс в актуальной документации. С удалением та же история
